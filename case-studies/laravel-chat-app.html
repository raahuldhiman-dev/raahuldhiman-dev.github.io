Multi-User
Real-Time Chat

A Laravel 13 API with a Vue 3 single-page app: Sanctum token auth, direct and group conversations, file attachments, unread tracking and typing indicators over self-hosted WebSockets. No paid services required.

01 — The Goal

Real-Time Chat Without a Vendor Bill

Most tutorials reach for a paid push service. This project does it with free, self-hosted parts.

💬

Real chat features

Direct and group conversations, attachments, unread counts and typing indicators, not just a message box.

🔓

Private by design

Only members of a conversation can read it, write to it, or listen to its channel.

💰

Free to run

A Pusher-compatible WebSocket server runs inside the app's own stack, so there are no per-message fees.

05 — Decisions

Calls That Mattered

The design choices that shape how the app behaves.

01

Self-hosted WebSockets

Using a Pusher-compatible server inside the stack removes per-message cost and keeps everything runnable locally.

02

A pivot table that carries role and read state

conversation_user stores each member's role and last_read_at, so membership, permissions and unread counts come from one place.

03

Check membership on every conversation endpoint

Each controller action first verifies the user belongs to the conversation, and returns 403 if not.

04

Save the message and the read marker together

Creating a message and updating the sender's last_read_at happen in one database transaction.

05

Broadcast to others only

Events are sent with toOthers(), so the sender's own client does not receive a duplicate of its message.

06 — Hard Parts

What Needed Care

The design problems in a real-time app.

🔒 Authorising live channels

Channels need their own authorisation, separate from HTTP routes. Channel callbacks check that the user is a participant of the conversation before they can listen.

✓ Participation checks per channel

👀 Unread state

Unread counts depend on who has seen what. A last_read_at per member and a mark-as-read endpoint keep it simple and cheap.

✓ Per-member read timestamp

📎 Safe attachments

Uploads are validated by size, stored under a controlled path and returned with a computed URL.

✓ Validation and controlled storage

🔄 Typing without noise

Typing is sent through a lightweight endpoint to a presence channel, kept separate from message storage.

✓ Separate event, no persistence
