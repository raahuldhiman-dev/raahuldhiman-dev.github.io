Case Study — AI Web App

Sentiment Analysis
with Google Gemini

A React and Vite app that analyzes text, chat-style conversations and chat screenshots with Google Gemini. It returns overall sentiment, a six-emotion breakdown, keywords and per-participant summaries, and keeps your history locally in the browser.

01 — The Problem

One Label Is Not Enough

A single "positive" or "negative" hides most of what is in a message, and chats involve more than one person.

🎭

Mixed feelings

A sentence can be mostly positive with some anger in it. Scores and an emotion breakdown show the mix, not just a label.

💬

Conversations

In a chat, each person has their own tone. The app scores each participant separately and summarizes the dynamic.

📷

Screenshots as input

People often have a chat as an image, not text. The app accepts a screenshot and reads the visible messages.

05 — Decisions

Calls That Mattered

How the app gets reliable results from a language model.

01

A strict, JSON-only prompt

The prompt embeds the exact output schema and states the rules: raw JSON only, scores as integers, and positive, neutral and negative must sum to 100. That makes the response something the UI can render directly.

02

Validate and normalize on the client

The response is checked and normalized before it is shown or saved, so one odd model answer cannot break the charts or corrupt stored history.

03

Separate prompts for text and conversations

Conversation mode asks for per-participant scores that each sum to 100 and a message-count estimate, which the single-text prompt does not need.

04

Local history, no backend

Saving to IndexedDB keeps the app free to host and keeps analysed text on the user's device.

05

Lazy-loaded tabs

Stats and Code load only when opened, which keeps the first load light.

06 — Hard Parts

What Needed Care

The problems that come with putting a language model behind a UI.

🧱 Structured output from a model

Models drift from a format. A schema in the prompt, explicit rules and client-side normalization turn free-form generation into predictable data.

✓ Schema-in-prompt plus validation

🖼️ Reading chat screenshots

Screenshots can be blurry or cropped. The conversation prompt tells the model to use only the text it can identify confidently, and to still return one participant if only one speaker is visible.

✓ Rules for unclear images

⏱️ Rate limits

API quota errors are normal on a free tier. The app reads the retry delay from the error and shows "Try again in about N seconds" instead of a raw failure.

✓ Friendly retry guidance

💾 Keeping history consistent

Results are stored in IndexedDB in a fixed shape, so History and Stats always read the same structure.

✓ One normalized result shape

08 — Limits

Known Limits and What Is Next

Honest notes on a client-side AI app.

🔑

API key handling

The demo calls Gemini directly from the browser. For production use, the key should live behind a small serverless proxy with rate limiting, not in the client.

🎯

Model scores are estimates

Scores come from a language model's judgement, not a trained classifier. They are good for exploration, and should not be treated as ground truth.

📐

What I would build next

A serverless proxy, batch analysis of many texts, CSV export of history, and evaluation against a labelled dataset.
